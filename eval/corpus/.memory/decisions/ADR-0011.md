# ADR-0011: Do Not Store Working Memory, Goals, or Tasks

## Context

Agents already have session state, and organizations already have issue trackers. Mirroring goals, tasks and transient working memory into the memory platform creates a second source of truth that becomes stale immediately.

## Decision

Do not model working memory, goals, or tasks as durable memory types.

The boundary, stated precisely:

**Out of scope — ephemeral cognition, owned by the agent:**
- current hypothesis
- current plan or todo state
- scratch notes and intermediate tool output
- transient task state

**In scope — durable knowledge, owned by memory:**
- what was learned
- what failed, and why
- what succeeded, and whether it is repeatable
- what decision was made, and its rationale
- what procedure works
- what constraint exists

The platform may ingest events from issue trackers and sessions as episodes, but it does not become the system of record for active work. Session state is summarised at session end; durable memories are extracted only at that boundary.

## Alternatives considered

1. Store complete agent working memory — rejected: half-life of minutes, concurrency and staleness problems.
2. Become a task or goal tracker — rejected: duplicates existing systems and expands the product past its remit.
3. Continuously mirror task state — rejected: another consistency problem for no retrieval benefit.

## Consequences

The memory platform stays focused on durable context. Agents and task systems remain responsible for ephemeral state.

If a future need appears genuinely durable but currently sits on the ephemeral side of this line, it is resolved by a superseding ADR, not by widening the definition informally.
