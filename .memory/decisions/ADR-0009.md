# ADR-0009: Deterministic Importance and Learned Utility

## Context

An LLM-generated importance score is difficult to calibrate, explain and reproduce, and once written it drives ranking forever. The system nevertheless needs to learn which memories are actually useful.

Importance, usefulness and truth are three different things.

## Decision

Compute an initial importance prior deterministically from stable properties: memory type, source trust tier, and whether the assertion was explicit. Do not use an LLM as the authority for importance.

Learn a separate utility signal from observed retrieval and outcome feedback. Utility starts neutral and only influences ranking after a memory has accumulated enough retrievals (>= 5) to avoid rich-get-richer behaviour on noise. Human pinning is a hard override.

Retrieval may combine the deterministic prior with learned utility, but both remain separately inspectable signals in the score decomposition.

### Invariant

```
utility = evidence about usefulness
trust   = epistemic authority
```

They are not substitutes. A frequently retrieved memory can be false; high utility must never raise trust tier. Correctness feedback, when it exists, adjusts trust through the review path — never through the ranking path.

Agent-sourced feedback is advisory and weighted below human feedback, so that an agent cannot promote its own writes.

## Alternatives considered

1. LLM-assigned importance — rejected: uncalibrated and self-reinforcing.
2. Static importance forever — rejected: actual usefulness changes as the project changes.
3. Utility-only ranking — rejected: new memories have no usage history and would never surface.

## Consequences

The system adapts to what is actually used while retaining a stable, explainable cold-start behaviour.

Utility weights are versioned artifacts; changing them is an evaluation-gated deployment.
