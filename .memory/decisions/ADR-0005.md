# ADR-0005: Trust Lattice and Quarantine for Generated Memory

## Context

Automatically extracted memory is not equivalent to human-confirmed knowledge. An extractor can misunderstand a conversation, infer a false relationship, or capture adversarial instructions embedded in a README, an issue comment, or a dependency's documentation.

A memory system that ingests arbitrary text and returns it to future agents is a long-term influence channel into future agent behaviour. That makes promotion a security boundary, not a ranking decision.

A confidence score alone cannot determine whether information is authoritative.

## Decision

Use an explicit trust lattice: `untrusted (0) < inferred (1) < observed (2) < verified (3) < authoritative (4)`.

Authoritative knowledge requires human confirmation through the Plane A review path, or a deterministic verification signal (CI pass, merged PR, tool outcome).

LLM-extracted observations and candidates enter quarantine. Quarantined material is not retrievable as authoritative context; candidates are never presented as trusted knowledge at all.

Quarantine is **not** a synonym for "low confidence." It means **untrusted derived material**. An item may carry `extractor_confidence = 0.99` and still be forbidden from authoritative retrieval.

### Fundamental invariant

```
confidence != trust
confidence != authorization
confidence != retrievability
```

Confidence is meaningful only *within* a trust tier.

### Lifecycle

```
SOURCE -> INGESTED -> SCREENED -> QUARANTINED -> { reject | expire | promote }
                                                        |
                                                        v
                                                     MEMORY -> AUTHORITATIVE
```

Screening runs before persistence: deduplication, secret scanning (hard reject, never silent redaction), and imperative-text heuristics that force instruction-shaped content to tier 0 and to the top of the review queue.

Retrieved memory is reference data, never instructions to the agent, and is rendered with its provenance visible.

## Alternatives considered

1. Promote when LLM confidence exceeds a threshold — rejected: model confidence is not a calibrated authorization mechanism.
2. Allow all extracted observations into retrieval — rejected: unreviewed content poisons context permanently and silently.
3. Treat all memory equally — rejected: provenance and trust are fundamental to safe memory.

## Consequences

The system is conservative about what becomes durable knowledge. This creates reviewer workload, which is why the review inbox is an operational component with explicit capacity limits and kill criteria (ADR-0015).

Rejection reasons are captured and become signal for tightening extraction.

## Acceptance test

No automatically extracted candidate can become authoritative because an LLM assigned it high confidence. A seeded adversarial instruction in a README is ingested, quarantined, flagged, and never returned as guidance.
